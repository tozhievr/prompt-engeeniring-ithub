# Учебное техническое задание №05 — ClipFlow

> **На разработку программного продукта «ClipFlow».** Структура адаптирована по ГОСТ 34.602-2020; документ не является официальным ТЗ на автоматизированную систему.

Дисциплина: Prompt Engineering / AI Software Engineering. Исполнители: команда из 2–3 студентов. Заказчик и принимающая сторона: преподаватели дисциплины. Версия: 1.0. Дата: октябрь 2026.

## 1. Общие сведения

**Наименование:** «ClipFlow». **Тип:** Сервис коротких видео. **Технологическая платформа:** HTML/CSS/JS + sql.js. **Развёртывание:** локальное веб-приложение, доступное по HTTP на компьютере пользователя.

Основание разработки: учебный командный проект по применению методов Prompt Engineering при разработке ПО.

## 2. Назначение и цели создания

Создать локальный прототип сервиса коротких видео с лентой и действиями пользователя.

Цель обучения: получить проверяемый программный продукт, обосновать требования и архитектуру, продемонстрировать применение ИИ и независимую проверку результатов.

## 3. Характеристика объекта автоматизации / предметной области

Объект разработки — автономный браузерный программный продукт категории «Сервис коротких видео». Предполагается один пользователь и работа без серверной инфраструктуры. Многопользовательские функции и удалённая синхронизация не входят в обязательный объём.

## 4. Требования к системе

### 4.1. Функциональные требования

- **FR-01.** Вертикальная лента минимум из пяти локальных видео.
- **FR-02.** Автовоспроизведение активного видео и остановка остальных.
- **FR-03.** Лайки с возможностью отмены.
- **FR-04.** Комментарии с просмотром и добавлением.
- **FR-05.** Профили авторов и фильтр по автору.
- **FR-06.** SQLite через sql.js: видео, авторы, лайки, комментарии.
- **FR-07.** Сохранение изменений между перезагрузками через IndexedDB.

### 4.2. Нефункциональные требования

- **NFR-01.** Приложение запускается в актуальном Chromium-совместимом браузере с локального HTTP-сервера.
- **NFR-02.** Для запуска не требуются Node.js, npm, Vite и сервер приложений.
- **NFR-03.** Ошибки выполнения JavaScript, препятствующие основным сценариям, отсутствуют.
- **NFR-04.** Интерфейс отображает состояние программы и доступные действия; есть понятный способ начать заново.
- **NFR-05.** Проект содержит README с инструкциями запуска и списком внешних зависимостей.
- **NFR-06.** Зависимости и обязательные медиафайлы поставляются локально, без обязательного обращения к CDN.
- **NFR-07.** SQLite исполняется в браузере через sql.js/WASM; база сохраняется в IndexedDB, а не на Python HTTP-сервере.
- **NFR-08.** Приложение не заявляет реальную серверную авторизацию, синхронизацию или постоянное хранение файлов на удалённом сервере.

### 4.3. Дополнительные функции (после выполнения обязательных)

- **OPT-01.** Подписки.
- **OPT-02.** Теги и поиск.
- **OPT-03.** Импорт локального контента.

## 5. Состав и содержание работ

1. Анализ ТЗ, выбор архитектуры, распределение ролей, подготовка первого промпта.
2. Реализация минимально работоспособной версии и фиксация ограничений.
3. Тестирование, устранение дефектов, улучшение интерфейса.
4. Оформление исходников, README, журнала промптов и тестового отчёта.
5. Демонстрация, защита и приёмка.

Сроки и контрольные даты устанавливаются преподавателем отдельно перед стартом проекта.

## 6. Порядок контроля и приёмки

Приёмка выполняется демонстрацией работающего проекта на локальном HTTP-сервере, проверкой обязательных требований и воспроизведением тест-кейсов. Преподаватели вправе предложить дополнительные граничные проверки в рамках ТЗ.

- **AT-01.** Повторный лайк отменяет предыдущий.
- **AT-02.** Комментарий сохраняется после перезагрузки.
- **AT-03.** Одновременно воспроизводится не более одного видео.

## 7. Требования к подготовке объекта к вводу в действие

Подготовить локальные зависимости и демонстрационные данные, проверить запуск командой `python -m http.server 8000` и открытие проекта в браузере. Необходимые лицензии и источники ресурсов указать в README.

## 8. Требования к документированию

- Исходный код проекта с историей изменений Git.
- `README.md`: установка, запуск, структура проекта, зависимости, участники.
- `PROMPT_LOG.md`: ключевые запросы к ИИ, итерации и анализ результата.

ГОСТ 34.602-2020 (адаптированная структура); материалы дисциплины; официальная документация sql.js и Web API.
